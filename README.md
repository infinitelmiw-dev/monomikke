# モノみっけ！ 投稿スタジオ

スマホで使える、APIキー不要・外部依存なしの投稿文章作成プロトタイプです。

## できること

- スマホ豆知識／スマホ便利グッズ／暮らしの便利グッズ／推し活グッズの4カテゴリー
- テーマと任意の紹介ポイントから、InstagramとThreadsの文章を同時に生成
- 文章の編集、コピー、自動保存、履歴の再編集・削除
- 下書き／投稿準備OK／投稿済みのステータス管理、履歴の絞り込み

生成はカテゴリー別テンプレートです。AI API、商品検索、事実確認、SNSへの自動投稿は行いません。特徴・価格・効果・対応機種などは投稿前に確認してください。Threadsは初期生成時500文字以内。編集で超過すると文字数を赤く表示します。

## Androidスマホだけで公開・利用する（おすすめ）

GitHub Pagesで無料のHTTPSサイトとして利用できます。PC・APIキー・パッケージインストールは不要です。

**[Androidだけで公開する手順](docs/ANDROID-PUBLISH.md)** を上から順に進めてください。GitHub Pagesの設定は `Deploy from a branch` → `main` → `/ (root)` です。公開するファイルは `index.html`、`style.css`、`generator.js`、`knowledge.js`、`topics.js`、`purchase.js`、`product.js`、`library-data.js`、`library-ui.js`、`carousel.js`、`image-loader.js`、`carousel-ui.js`、`app.js` と任意の `.nojekyll`。すべて同じ階層に置きます。相対パスのため `/monomikke/` のようなサブパスでも動作します。

Pull Requestを使えば、スマホでマージしてPagesを有効にするだけで公開できます。ZIPのダウンロードやファイルの手動アップロードは不要です。実際の公開完了は、マージとPagesの設定後に確認してください。履歴は利用者のブラウザ内に保存され、旧URLから新URLには自動移行されません。

開発環境でスマホ用の配布ZIPを作り直す場合：

```sh
python3 scripts/package-pages.py
```

チェックアウトの隣に `monomikke-pages.zip` を生成します。ZIPを解凍して中のファイルをGitHubにアップロードしてください。

## PCでローカル起動（開発用）

Python 3があるPCで、このフォルダーを開いて実行：

```sh
python3 -m http.server 3000 --bind 0.0.0.0
```

PCのブラウザで `http://localhost:3000` を開きます。Node.jsもある場合は `npm start` でも同じサーバーを起動できます。依存パッケージのインストールは不要です。

## スマホで確認

1. このフォルダーのファイルをPCに用意し、上のサーバーを起動します。
2. PCとスマホを同じWi-Fiにつなぎます。
3. PCの設定でローカルIPv4アドレスを調べます（Windows: `ipconfig`、Mac: システム設定 → Wi-Fi → 詳細 → TCP/IP）。
4. スマホのSafariまたはChromeで `http://PCのIPv4アドレス:3000` を開きます。例： `http://192.168.1.20:3000`。スマホ側のlocalhostはPCには接続しません。
5. 接続できなければPCのファイアウォールでプライベートネットワーク上のPython受信を許可し、ゲストWi-Fiの端末間通信制限も確認します。

クラウド内のlocalhostにはスマホから直接アクセスできません。この手順はPCにファイルを用意した場合です。常時アクセスする場合は静的サイトとしてHTTPS配信できますが、この作業では外部公開していません。

コピーはHTTPSまたはlocalhostでClipboard APIを使用します。LAN上のHTTPなどで利用できない場合は従来のコピーを試し、失敗したら文章を選択して手動コピーを案内します。

履歴は同じブラウザ・同じURLのlocalStorageに保存します。別端末や別URLとの同期・バックアップはありません。プライベートブラウズやデータ削除では消失する場合があります。保存できない場合は画面に通知します。

## 具体的な投稿を作る

投稿スタイルは「豆知識・解説型」「共感・あるある型」「商品紹介型」「おすすめ・比較型」から選べます。Instagramは項目別の詳しい解説、Threadsは要点を絞った文章を生成します。生成ごとに導入や保存への誘導を切り替えます。コメント募集は付けません。商品リンク誘導には実際のHTTPS URLが必要です。

内蔵テーマはフォーム内の「内蔵データで試せるテーマ」に記載しています。機種・OSが違う手順や特定商品の性能を推測で補いません。スマホ豆知識は33件（今回30件追加）。表記・助詞・付加的な語句を正規化して登録語句を検索し、対象OSが明らかに違う候補や曖昧な候補を避けます。任意入力がある場合は内蔵の具体的な説明より優先します。伝えたいポイントは完全に任意です。未登録テーマも追加確認が必要な箇所を示した一般的な下書きを生成します。比較型は確認項目を示す形式で、データのない商品ランキングは生成しません。利用者の入力内容の正確性を自動検証する機能はありません。

### 生成部分の構成

- `knowledge.js`: カテゴリーごとの確認手順・選択基準・注意点。追加の豆知識は一般的な確認方法で、端末固有のボタン操作や効果を断定しません。スマホ設定には公式情報の参照先を記載。商品データは一般的な選び方で、特定商品の仕様は含めません。
- `generator.js`: 入力判定・スタイル・SNS別の文章構成。`generatePost(input, provider)` が非同期の拡張窓口です。providerは `generate(input)` で `{instagram, threads}` を返します。将来のAI接続ではサーバー側にキーを保持し、Pagesにはキーを置かないでください。
- `app.js`: フォーム・保存・履歴。従来と同じlocalStorageキーを使用し、旧履歴はそのまま読み込みます。古い投稿の文章は自動で書き換えません。

ビルドは不要です。Pages更新時には `knowledge.js` も必ず同じ階層に配信します。

## 第4弾：ネタ提案・書き出し・別パターン

- カテゴリーを選んで「今日の投稿ネタを探す」を押すと、内蔵の候補から3件表示。スマホ豆知識18件、他の3カテゴリー各16件を用意。最新情報の取得は行いません。
- 候補を押すとテーマへ入力します。シャッフルした候補を順番に使い、直前の3件を次の表示から除外。カテゴリー別の表示履歴は `monomikke.topics.v1` に保存します。保存できなくても画面内の提案は利用できます。
- 書き出しは共感型・疑問型・意外性型。意外性型は確認視点を変え、未確認の効果や流行は断定しません。
- 「別パターンを生成」は現在のフォームを使い、両SNSをまとめて別の下書きへ生成。書き出しと、注意点・本文・誘導の配置を3通りで切り替えます。設定の操作順は変えません。元の編集済み文章や投稿ステータスは元の履歴に残します。履歴を開くと書き出し設定も復元します。旧履歴は共感型として扱い、文章は書き換えません。
- ネタ提案は `topics.js`、書き出し・構成変更は `generator.js`。外部API・追加パッケージ・APIキーは不要です。

第4弾のテストは `node --test tests/*.test.cjs` で実行できます。

### GitHub Pagesの更新

AndroidのChromeでこの変更のPRを開き「Merge pull request」→「Confirm merge」。Pagesが既存どおり main / (root) を配信していれば追加設定は不要です。「Actions」で pages build and deployment の成功後に公開URLを再読み込みしてください。`topics.js` も同じ階層へ配信されます。履歴を残すため、Chromeのサイトデータは削除しないでください。更新前後で同じURL・ブラウザを使用します。

## 第5弾：Instagram投稿画像メーカー

投稿を生成・履歴から開く → 「Instagram投稿画像メーカー」を開く → デザインを選ぶ → 「文章から画像を作る」。表紙・解説・まとめの3枚を1080×1350pxで作り、各「PNGで保存」から1枚ずつダウンロードします。Android Chromeでは「︙ → ダウンロード」またはFilesアプリからPNGを確認できます。端末のInstagramで3枚を順に選んで投稿してください。自動投稿は行いません。

- クリーム、くすみピンク、セージグリーンの3デザイン。全画像に「モノみっけ！」を表示。
- Instagram文章を出典に表紙・解説・注意点等へ配分。生成時点の文章を保持し、事実を追加・要約しません。各画像の見出しと本文を自由に編集可能。投稿の文章そのものは変更しません。
- 日本語を文字単位で計測し、禁則を考慮した改行と文字サイズ調整を行います。収まらなければエラーを表示してPNG保存を無効にします。黙って省略しません。
- 画像編集とデザインは既存の投稿に追加データとして保存。旧履歴はそのまま利用可能。元の文章変更時は差分を通知し、画像の編集を自動上書きしません。「文章から画像を作る」で確認して作り直せます。
- ロゴは任意の2MB以下・4096px以下のPNG/JPEGを選択。ブラウザ内のみで処理し、この画面を閉じる・再読み込みすると選び直しになります。画像自体は履歴に保存しないため、履歴容量を抑えます。
- `carousel.js` は原文配分・改行・Canvas描画、`carousel-ui.js` は編集・PNG保存。ビルドも外部APIも不要。Pagesには両ファイルも同じ階層へ配信してください。
- 書き出しにテーマの語句を使い、別パターンでは「実際の確認項目数」「先に注意点」「チェックリスト」の構成を切り替えます。データが2項目なら3選と表示しません。

検証は `npm test`。Android実機での操作確認は、Pages更新後にPNGを保存して行ってください。開発時はChromiumのスマホ相当画面とPNG出力で検証しています。

## 第6弾：写真入りの商品紹介画像

1. 必要なら「商品紹介・アフィリエイト情報」を開き、商品名・確認済みの特徴・メリット・価格・注意点・商品URLを入力します。未確認の項目は空欄にします。価格には税込・確認日などを添えてください。PR表示のチェックで広告であることを明示できます。
2. 通常どおり文章を生成し、「Instagram投稿画像メーカー」→「文章から画像を作る」を押します。
3. 利用権限の確認にチェックし、商品写真をAndroidのギャラリー／Filesから選びます。JPEG・PNG・WebP、1枚15MB以下、合計6枚まで。写真は順番に各スライドへ割り当てられ、選択欄から変更できます。
4. 各スライドの「全体表示」「枠いっぱいにトリミング」を選び、拡大縮小・上下左右のスライダーで位置を調整します。プレビュー上のドラッグ・2本指のピンチでも調整できます。縦横比は変えません。商品全体を見せる場合は全体表示を使ってください。
5. 各画像の見出し・本文、背景色・文字色・本文最大文字サイズを調整します。写真の領域と文字の領域は分かれています。文字が収まらない場合は内容を短くしてください。文字サイズは設定値以下へ自動調整します。
6. 1枚ずつ「PNGで保存」→Chromeのダウンロード／Filesで確認。写真・ロゴの変更後は必要なPNGを再保存します。

クリーム・シンプル／くすみピンク・かわいい／セージグリーン・ガジェットの3デザイン。ロゴ追加は従来どおり任意のPNG/JPEGを選択します。

写真はブラウザ内のImageBitmapのみで保持し、最大辺1600pxへ縮小してメモリ使用量を抑えます。4000万画素超は縮小した画像を選び直してください。写真のデータはlocalStorageやGitHubへ保存せず、外部にも送信しません。ページを閉じる・再読み込みすると消えます。「読み込んだ写真をすべて削除」でも解放できます。履歴には文章・デザイン・位置調整値だけを保存し、写真入りPNGの再作成には写真の再選択が必要です。URLから画像を取得しません。写真の撮影日時・位置情報を読み出す機能もありません。

商品紹介モードは入力した情報を使い、価格・性能・レビューを補完しません。確認できていない注意点は追加確認が必要と明記します。楽天等のHTTPS商品リンクはそのまま利用できます。リンク先の内容は取得せず、PR表示と入力内容は投稿前に確認してください。

`product.js` が商品文章と写真の配置計算を担当します。Pagesへはこのファイルも配信します。ビルド・APIキーは不要です。旧履歴や旧画像メーカーは引き続き利用できます。

Android Chrome相当のユーザーエージェント・スマホ画面・タッチ対応のChromiumで検証します。Android実機はこの環境では未接続のため、公開後にギャラリー選択とダウンロードの実機確認を行ってください。

## 第7弾：楽天アフィリエイト商品管理とバックアップ

「楽天アフィリエイト商品管理」を開くと、商品名・4カテゴリー・URL・特徴・メリット・注意点・価格・確認日・ステータスを登録できます。商品名で検索し、未投稿／投稿準備OK／投稿済みで絞り込み、編集・削除できます。削除しても作成済みの投稿は消えません。商品と投稿のステータスは別々に手動管理します。

「投稿作成へ入力」で登録情報をフォームへ転記します。PR表示をオン、Instagramの誘導をプロフィールに設定します。価格確認日も文章に含めます。Instagramはプロフィールへの案内、Threadsは入力した原文リンクを使用します。「リンク原文をコピー」はURLを変更・短縮・デコードせずコピーします。長いリンクがThreadsの500文字に収まらない場合は、原文を短縮せず本文に未掲載と明記した下書きを生成します。リンクは台帳から別途コピーできます。楽天の商品検索API・ページ取得・画像取得は行いません。公開前にリンク・価格・広告表示を確認してください。

### 写真の種類

写真の読み込み前に「自分で撮影した写真」「利用が認められた提供画像」を選びます。提供画像は、読み込んだ時点の種類をその写真に固定し、全体表示のみ・移動／拡大／切り抜き禁止にします。種類の選択を後から自分の写真に戻しても、読み込み済み提供画像の制限は解除されません。画像には文字や装飾を重ねず、写真領域の外に配置します。ロゴも写真の外側に表示します。

楽天等の最新利用条件を利用者が確認し、SNS向けの画像への使用が認められている提供画像のみ読み込んでください。この機能で権利確認や利用許諾を取得することはできません。写真の無断取得や外部送信は行いません。

### JSONバックアップと復元

「商品・投稿履歴をJSONでバックアップ」で、AndroidのDownloadsに保存します。「JSONから復元」からファイルを選択し、件数を確認して復元します。形式・型・長さ・日付・URL・重複IDを検証してから反映します。確認前・検証エラー時は保存内容を書き換えません。同じIDはバックアップ側で更新し、他のデータは残します。復元後は通常の編集・再読み込みで確認してください。

- JSONは2MBまで、商品・投稿それぞれ1000件までのバックアップ形式。復元前にも現在のバックアップを取ることをおすすめします。
- 写真やロゴの画像データは含めません。文章・デザイン・写真位置の数値設定のみ含みます。写真は再選択が必要です。
- 商品台帳は `monomikke.products.v1`。従来の投稿キー `monomikke.posts.v1` は変更せず、旧履歴も保持します。
- ブラウザのサイトデータを削除すると保存内容も消えます。別端末への移行はJSONで行ってください。JSONには商品URLや投稿文章が含まれるため、GitHubの公開リポジトリにアップロードしないでください。

Pagesの設定は従来のmain / (root)のままで動作します。追加の `library-data.js` と `library-ui.js` も同じ階層へ配信してください。秘密情報・APIキーは不要です。商品登録やJSON復元は公開操作ではなく、SNS投稿やリンクの公開は利用者が確認して行います。

## 第8弾：購入につながる紹介文・楽天画像モード

商品情報の「紹介文モード」で「購入につながる紹介文」を選び、共感型／便利さ重視型／比較検討型を選択します。必要なら想定する読者の悩みを入力し、通常どおり生成します。悩み → 確認済みの特徴・メリット → 購入前の注意点 → 商品ページへの誘導の構成です。未入力の性能・価格・レビュー・使用経験は作成せず、足りない情報は要確認と示します。比較検討型も、未入力の比較対象や優劣を創作しません。購入の成果を保証する機能ではありません。

Instagramは詳しい紹介、Threadsは確認ポイントを絞った文章にします。PR表示・プロフィール誘導・原文URLの維持は従来どおりです。表紙タイトル案を画面に表示し、「別パターンを生成」でタイトルと表現・見出しを切り替えます。書き出しの共感型等は従来モードに、購入モードの3パターンは新しい専用選択欄で適用します。

画像作成時は、生成時のInstagram文章から以下の3枚を用意します。生成後に元文章を編集した場合は、古い内容を混ぜず編集済み文章を元に通常の配分を使います。

1. 短い見出し・商品名・悩みと商品写真
2. 入力された特徴・メリットと、入力があれば価格・確認日
3. 注意点・購入案内

画像内の文章は編集可能です。長い見出しは計測・改行・縮小し、収まらなければ編集を案内してPNG保存を止めます。新しい設定と画像文章も既存の投稿履歴・JSONバックアップに含めます。

### A・B・Cの写真モード

- A：自分で撮影した写真。従来の拡大・移動・トリミングを利用可能です。
- B：楽天アフィリエイトのリンク作成ページから、利用者が適切にダウンロードした画像。全体を縦横比を維持して表示し、トリミング・移動・拡大・フィルターを無効にします。「楽天市場の商品」は画像外に描画し、見出し・説明・ロゴ・装飾も画像外に配置します。
- C：写真なし。読み込み済み写真を削除せず非表示にし、画像選択・写真編集を無効にします。A/Bへ戻せば画面内の写真を再利用できます。

Bは画像の権利・入手元・利用条件を判定する機能ではありません。利用者が楽天の最新利用条件と許諾範囲を確認してください。楽天の商品ページやリンク作成ページから自動取得はしません。写真・ロゴは画面内だけで保持し、再読み込み後は再選択が必要です。

追加の `purchase.js` を既存ファイルと同じ階層に配信します。main / (root) のPages設定はそのまま利用できます。Android Chrome相当のChromium検証であり、Android実機は未接続です。

## 自然な商品紹介文への改善

購入モードは事務的な見出しを使わず、読者の悩みを共感の書き出しへつなぎ、入力済みのメリットを特徴より先に紹介します。性能から未入力のメリットを推測せず、情報がない場合は商品ページでの追加確認を案内します。Instagramは親しみやすい段落、Threadsは短い別文章です。

表示名は「【公式】」「【送料無料】」等の既知の販促表記と余分な空白のみ整理します。ブランド、型番、ワット数、色、端子など商品を識別する情報は勝手に省略しません。安全に短くできなければ正式名称を使います。例：`【公式】【送料無料】 Anker PowerPort III Nano 20W` → `Anker PowerPort III Nano 20W`。正式名称は商品登録・投稿履歴に保持し、表示名も履歴・JSONに保存します。

Ankerのテストは商品名だけの入力で性能・価格・体験談を補わないケースと、明示的なテスト用入力のメリットを優先するケースを検証します。実商品の仕様やレビューを外部から取得・確認する機能はありません。

## Androidで画像が開けない場合の修正

写真は拡張子・MIMEだけでなくファイル先頭のJPEG/PNG/WebP署名で判定します。空のMIMEや`application/octet-stream`、実形式と異なるMIMEでも、実データが対応形式なら読み込みます。`createImageBitmap`が失敗・未提供・タイムアウトの場合は、ローカルBlob URLの画像要素で読み込みます。縮小はCanvasで行い、2度目の`createImageBitmap`のリサイズ対応に依存しません。外部通信や写真の永続保存は行いません。

読み込み後はサムネイルとファイル名を表示し、今回の最初の成功写真を1枚目へ割り当てます。まだ画像を作成していなければ3枚を自動作成します。サムネイルを押して1枚目の写真を選び直せます。複数選択の一部だけ失敗しても、成功した写真は保持します。既存写真をすべて削除してから選び直すこともできます。

空ファイル、15MB超、非対応形式、ファイルアクセス失敗、破損・未対応の画像データ、タイムアウト、4000万画素超、描画時のメモリ不足等を日本語で案内します。デコード失敗だけでは端末側の原因を断定できないため、保存し直し・実際の画像変換・小さい画像での再試行を案内します。拡張子の変更だけでは変換されません。Bの画像は引き続き全体表示・編集禁止で、文字と装飾は画像外です。

文字量が多く画像を書き出せない場合も写真は表示し、文字量の警告とPNG保存無効で修正を促します。従来の「文字エラーで写真も非表示」にはしません。ロゴも同じ代替読み込みを使います。

### 実画像を使うブラウザテスト

通常の `npm test` に加え、PlaywrightとChromiumを備えた開発環境で実行：

```sh
npm run test:images
```

`CHROMIUM_PATH` でChromiumを指定可能です。アプリ自体にはPlaywrightも追加パッケージも不要です。テストはローカル専用サーバーを自動起動・終了し、実際のJPEG/PNG/WebPデータを生成して読み込みます。Bitmap成功/失敗/未提供/停止、画像要素の代替処理、MIME欠落、破損、サムネイル、1枚目再割り当て、文字量超過時の写真表示、PNG出力を確認します。実際に失敗した楽天Ankerファイルは未提供のため、同一ファイル・Android実機での再現確認は別途必要です。

新規 `image-loader.js` も他のJSと同じ階層へ配信します。Pages設定は従来のmain / (root)のままです。

## 大人かわいい・雑誌風（セージ）テンプレート

画像メーカーの「デザイン」から選択します。従来の3デザインも引き続き使えます。

- 1枚目：大きな見出し、商品写真、淡いピンクベージュの紹介カード。
- 2枚目：淡いセージ・ピンク・クリームの3つのポイントカード。本文を空行（または改行）で区切って配置します。4項目以上は3つ目のカードにまとめ、文章を省略しません。足りないカードは未入力と明記し、商品の魅力を創作しません。
- 3枚目：注意点のカードと、セージグリーンの購入案内帯。

写真がない場合も利用可能です。楽天提供画像は元画像全体を縦横比を維持して表示し、見出し・カード・装飾・ロゴは写真の外側に配置します。長文が収まらない場合は省略や文字切れで保存せず、編集を案内します。デザイン・編集内容は既存の履歴とJSONバックアップに保存します。

`node tests/browser/magazine.cjs` で、スマホ相当Chromiumの3枚PNG保存・1080×1350・提供画像の全体表示・編集禁止・文字量超過・履歴復元を検証できます。開発用Playwright/Chromiumが必要です。アプリは引き続き無料・APIキー不要で、既存のPages設定から配信できます。

## 第11弾：履歴・画像編集が開かない場合の修正

古い描画コードと新しい保存テンプレートの組み合わせで、未登録テーマ色の `bg` を参照して例外が発生し、画像編集だけでなく履歴を開く処理も止まるケースを再現しました。実際の端末のJSログは未取得ですが、この再現条件を修正しています。

- 全JS/CSSの読み込みに共通の版番号を付け、古い資産の混在を避けます。今後JS/CSSを更新する際もHTMLの共通版番号を更新します。
- 未対応テンプレートでも投稿文章・保存済み画像文章の編集画面を開き、再読み込みを案内します。未対応デザインを勝手に別デザインとして保存しません。
- プレビューの例外は各画像内で扱い、投稿の編集・履歴への移動を止めません。
- 投稿未選択時は「先に投稿を生成するか、投稿履歴から選ぶ」旨を通知します。
- 表示用の写真初期値を開いただけで保存データへ追加しません。未対応の投稿形式は削除せず保持し、読み取れないJSONは上書き保存を停止します。既存データの削除・リセット・初期化は行いません。

`node tests/browser/editor-recovery.cjs` で、古い描画コード・描画例外・旧画像形式・未選択、新旧4デザインでの生成/PNG保存、既存投稿・商品・編集済み文章の保持、読み取れない保存データの保護を検証します。通常の `npm test`、`npm run test:images`、`node tests/browser/magazine.cjs` も実行します。ブラウザテストはAndroid Chrome相当の画面・タッチ設定でのChromium検証であり、Android実機は未接続です。

マージ後、Pagesデプロイ成功を確認して通常の再読み込みを行ってください。ブラウザのサイトデータは削除しないでください。Pages設定・無料/APIキー不要の構成は変更していません。

## ページごとの文字配置

画像編集の各ページに「見出しの配置」「本文の配置」を追加しました。それぞれ左揃え・中央揃え・右揃えを選択できます。初期値は従来どおり左揃えです。変更はそのページだけへ適用され、プレビューと保存するPNGへ直ちに反映されます。画像用の文章を作り直す場合は新しいスライドになるため、初期値に戻ります。

雑誌風1枚目のピンクベージュ枠内は「本文の配置」で中央揃えにできます。2枚目は番号部分を避けた各カードの本文領域、3枚目は注意点カード内で揃えます。見出し・本文は従来の幅・高さ・余白の範囲内で行ごとに位置調整するため、写真の領域や装飾の位置は変えません。長文の改行・縮小・保存停止による文字切れ防止も維持します。装飾ラベルや購入案内帯の固定文言はデザインを維持します。

各スライドの`titleAlign`/`bodyAlign`を履歴とJSONバックアップへ保存します。設定のない旧履歴は左揃えで表示し、開くだけでは保存データへ既定値を書き込みません。楽天提供写真の全体表示・加工禁止は維持します。

`node tests/browser/text-alignment.cjs` で、Anker PowerPort III Nano 20Wの投稿を使い、見出しとピンクベージュ枠の実際の左/中央/右の描画位置、写真画素の不変、ページ別保存と復元・バックアップ、PNG保存を検証できます。スマホ相当Chromiumでの検証で、Android実機は未接続です。Playwright/Chromiumは開発テスト用で、アプリに追加の依存・料金・APIキーは不要です。

このブランチは、mainに未反映だった前回の履歴・画像編集停止の修正も含みます。Pages設定は従来のままです。マージ後は通常の再読み込みで使えます。サイトデータは削除しないでください。
